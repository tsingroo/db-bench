## 一些常见关系型以及NoSQL数据库的Benchmark测试

#### 说明
- 和`web-server-bench`项目一样，数据只作为参考。各种配置未做优化
- 比如如果使用`redis-bench`工具测试的同机房的`GET`命令的QPS为10W，你的网站活跃用户为10W，就算你应用做了多机负载均衡，瓶颈还是会在Redis出现，因为很多网站会在中间件里面检查Jwt是否在Redis中存在。你应该了解这个值，以便知道在什么量级的情况下需要更改方案或者散列到不同的Redis上。
- 一些网站甚至会在中间件中去数据库查询用户状态，如果MySql的简单单表查询都达不到3千，你就得考虑优化这个逻辑。


#### 要测试的数据库
- MySQL
- MariaDB
- PostgreSQL
- Redis
- MongoDB
- ScyllaDB
- InfluxDB
- ClickHouse


#### 只做一些简单场景的测试
- 单表查询，不带索引、带索引
- 单表插入，不带索引、带索引
- 单表散列到10张表,带索引的插入、删除
- 两表查询，不带索引、带索引和联合索引
- 三表查询，不带索引、带索引和联合索引
- 只使用go或者Rust来测试，但是可能会使用不同的ORM框架
- 只在几种ECS实例下测试
